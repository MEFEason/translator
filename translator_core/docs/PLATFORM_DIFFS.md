# 平台差异说明（Windows ↔ Android）

> 本项目同一套代码出两端：**Windows 桌面端**与 **Android 移动端**。
> 两端**功能定位一致**（视频会议实时字幕翻译），但**交互形态天然不同**。
>
> 本文档记录**有意为之的差异**，避免后来者误以为是「漏做」而去「修」。
> 2026-10-28 用户明确：**端与端之间功能微小不同可以理解**，差异写在这里即可。

---

## 一、差异的总原则

| 原则 | 说明 |
|---|---|
| **能力对齐，形态不对齐** | 两端都能做的事（转写、翻译、字幕窗、声源、说话人标签、词库）**都必须有**；做事的**方式**允许不同 |
| **不做没意义的复制** | 桌面的「托盘 + 多窗口 + 二次询问」是桌面交互习惯，搬到手机上反而是倒退 |
| **不静默降级** | 任何一端拿不到能力（如内放不可用），必须**显式提示**，不能悄悄降级（DESIGN §2.5.2） |
| **平台权威判定** | 设备形态（手机/平板）、权限状态、窗口尺寸等，一律由**该平台的原生层**判定，Dart 侧不猜 |

## 二、功能矩阵

| 功能 | Windows 桌面端 | Android 移动端 | 差异性质 |
|---|---|---|---|
| 实时转写（ASR） | ✅ | ✅ | 无差异 |
| 离线翻译（MT） | ✅ | ⏳ 交叉编译中 | 进度差异，非设计差异 |
| 系统内放采集 | ✅ WASAPI loopback | ✅ AudioPlaybackCapture | 平台 API 不同，语义一致 |
| 麦克风采集 | ✅ | ✅ | 无差异 |
| **双路并行采集** | ✅ | ✅ | 无差异（2026-10-28 补齐） |
| 说话人标签（对方/我） | ✅ | ✅ | 无差异 |
| 词库（术语替换） | ✅ | ✅ | 无差异 |
| 字幕悬浮窗 | ✅ 独立第二实例窗口 | ✅ 原生 Overlay 悬浮层 | **形态不同，能力一致** |
| 字幕窗可调整大小 | ✅ 拖边角 | ❌ 固定满宽两行 | **有意差异** |
| 字幕窗横向滚动 | ❌（多行堆叠） | ✅ 超宽时自动滚动 | **有意差异**（见 §4） |
| 关闭主界面时 | 询问 / 最小化到托盘 / 退出（三选一） | 直接退到后台，常驻通知继续转写 | **有意差异**（见 §3） |
| 系统托盘 | ✅ | ❌ | 平台无此概念 |
| 「显示主窗口」恢复入口 | ✅ 设置页 | ❌（桌面图标/最近任务即可） | 平台无此概念 |
| 屏幕方向 | 任意 | 手机锁竖屏 / 平板可旋转 | 平台形态决定 |
| 转写盘目录 | 桌面 `translate results` | 应用外部私有目录 | 平台权限模型决定 |
| **导出转写** | file_picker 选路径 | 复制到剪贴板 + 系统「另存为」目录选择 | **形态不同，能力一致**（见 §5） |
| 模型分发 | 安装包内（随 exe） | APK assets → 首启解压到内部私有目录 | 平台安装模型决定 |
| 版本号端标识 | `windows-{channel}-v{x.y.z}-{时间}` | `android-{channel}-v{x.y.z}-{时间}` | 单一来源，端标识区分 |

## 三、关闭行为：桌面三选一 vs 手机直接后台

### Windows 桌面端

点 ✕ 弹窗询问：最小化到通知栏 / 退出程序，可勾选「记住选择」。
理由：桌面上「关窗口」常被理解为「我不想看到了，但别杀我」，
    系统托盘是 Windows 用户的既有心智模型。

### Android 移动端

点 ✕ 直接退到后台，**转写继续**（前台服务 + 常驻通知）。

理由：
1. 手机没有托盘，弹窗询问是**桌面习惯硬搬**，属功能倒退；
2. Android 本身就是「切后台继续跑」的心智（微信、录音机都这样）；
3. 常驻通知已经提供了**明确的可见性与控制**（通知栏可「停止转写」）。

> **实现约定**：`capability_page.dart` 里「关闭时询问 / 最小化到通知栏 / 退出程序」
> 与「显示主窗口」四项，统一用 `Platform.isAndroid` 分支，**仅桌面端显示**。
> Android 端对应位置显示「后台运行」说明块。

## 四、字幕窗：桌面多行堆叠 vs 手机满宽两行滚动

### 需求来源

用户 2026-10-28 定版：手机端字幕窗**固定两行、宽度吃满屏幕**，
**第 1 行英文（原文）、第 2 行中文（译文）**。

### 为什么手机端不照抄桌面的多行堆叠

桌面歌词窗是**独立窗口**，可以拖边角调大，纵向堆 4~6 行没问题。
手机屏幕纵向本就紧张，且会议场景下字幕窗往往压在视频画面上 ——
多行会遮挡人脸。**满宽两行**是手机上的最优解。

### 随之而来的滚动需求

两行固定 → 一句话长了必然超宽 → 必须能滚动看全。
Android 端实现了**自绘滚动**（`ScrollingTextLine`）：

- 文本未超宽 → 静止贴左
- 文本超宽 → 匀速右滚，末尾停顿 1.2s，回开头循环
- **流式更新时滚动位置跟随最新内容**（新字立刻可见）

### 为什么不用系统 marquee

`TextView.ellipsize = marquee` 在此场景有三个问题：
1. 需 `isSelected = true` 才滚动，Overlay 里不可靠；
2. 速度固定不可调；
3. **文本被替换时滚动位置重置到开头** —— 而字幕是流式的（partial 不断变长），
   每次识别更新都把内容弹回开头，用户永远看不到刚说出口的字。

### 桌面端不改

用户 2026-10-28 明确：**「Windows 能改大小不用改」**。
桌面端保持「独立窗口 + 可拖边角调大小 + 多行堆叠」，不引入滚动逻辑。

## 五、导出转写：桌面选路径 vs 手机复制 + 另存为

### Android 端（2026-10-28 用户需求）

> 「导出不能是导出到软件目录，要点击之后复制并打开目录选择」

两步：

1. **复制**：内容进系统剪贴板 → 可直接粘到微信 / 文档 / 邮件
2. **另存为**：SAF `ACTION_CREATE_DOCUMENT` → 系统弹目录选择 + 文件名输入
   → 写到用户指定位置（Downloads / 微信收藏 / 网盘…）

**为什么不能写应用私有目录**：Android 11+ 分区存储下，应用私有目录
在文件管理器里**用户根本看不到**，等于导出了也拿不到。

**为什么不用 `file_picker.saveFile`**：8.x 在 Android 上不支持
（抛 `UnimplementedError` / 返回 null）。这正是旧实现退化成
「写应用私有目录」的原因。

**为什么不需要存储权限**：SAF 自带授权，用户选中的 URI 即为授权范围。

### Windows 端

维持 `file_picker.saveFile` 选路径（桌面没有 SAF 对应物，
Windows 侧应用本来就有文件系统权限）。

## 六、其他已知的形态差异

| 项 | 差异 | 原因 |
|---|---|---|
| 屏幕方向 | 手机锁竖屏、平板可旋转 | Manifest 静态声明无法区分设备，运行时按 `smallestScreenWidthDp` 收紧（`OrientationPolicy.kt`） |
| 导航形态 | 平板用 `NavigationRail` 侧栏，手机用底栏 | 宽屏侧栏更易触达 |
| 正文宽度 | 平板页宽限 840/960dp | 宽屏下不限宽则行长过长、可读性差 |
| 转写盘 | 手机在应用外部私有目录 | 桌面默认 `$HOME/Desktop` 在手机上不存在 |
| 托盘菜单 | Windows 有（打开/转写/退出），Android 无 | 平台无托盘概念；Android 的等价物是**通知栏动作** |
| 悬浮窗权限 | Android 须跳系统设置页手动授予 | `SYSTEM_ALERT_WINDOW` 不走运行时弹窗（桌面无此权限） |

## 七、判定平台差异的原则（给后续开发者）

1. **先问：这个差异是平台能力限制，还是形态惯性？**
   - 能力限制（如 Android 无托盘）→ 记入本文档，做功能等价替代
   - 形态惯性（如桌面三选一询问）→ **不要搬到另一端**
2. **两端能力缺口必须显式提示**，不能静默降级（DESIGN §2.5.2）
3. **平台判定一律下沉到原生层**（Kotlin / Win32），Dart 侧不猜
4. 新增差异时**先更新本文档**，再改代码
